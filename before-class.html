The checklist

The sections below explain each item.

1. Install and sign in

You need four things on the laptop you will bring.

  • Claude Code on a Claude Pro or Max subscription, or with an Anthropic API key. A free Claude.ai account does not work with Claude Code. Install it with the native installer (macOS, Linux and WSL):

    curl -fsSL https://claude.ai/install.sh | bash

    Then run claude in any folder and follow the login steps. Homebrew (brew install --cask claude-code) also works. Anthropic’s setup guide has the current commands for every platform.

  • Python 3.9 or later with pandas and matplotlib. If you work mainly in Stata, install Python anyway. The labs use Python, and Claude writes the code.

    • Mac: python3 -m pip install --user pandas matplotlib. If pip refuses with “externally-managed-environment”, add --break-system-packages to the end.
    • Windows (inside Ubuntu/WSL): sudo apt update && sudo apt install -y python3-pandas python3-matplotlib unzip

  • git, which comes with macOS (run git --version; if it is missing, macOS offers to install it) and is already installed in Ubuntu/WSL. Tell git who you are, or your first commit in class fails with “Author identity unknown”. Run these once, with your own name and email:

    git config --global user.name "Jane Doe"
git config --global user.email jdoe@stanford.edu

  • A GitHub account, free at github.com.

Windows users: Claude Code runs inside WSL2, a Linux system that Windows provides, not in PowerShell. Open PowerShell as administrator, run wsl --install, reboot, and then do everything on this page inside the Ubuntu window. Keep your project folders under your Linux home folder (cd ~), not under C:\Users.

The full course’s General Setup page walks through each step in more detail, with fixes for the common failures. It asks for the course access code, Barrios_AI2026. Ignore its WRDS steps for now.

How you know it’s done: in a terminal, each of these prints a version, ok or your email:

claude --version
python3 --version
python3 -c "import pandas, matplotlib; print('ok')"
git --version
git config --global user.email

and you can sign in to GitHub in a browser.

2. Run the smoke test

The smoke test checks that Claude Code can do real work on your machine: read and write files, run Python, and fetch a public SEC filing.

  1. Download the starter pack and unzip it in your home folder, so the files end up in ~/stanford_starter/. Its README.md says what each file is for.

    • Mac: move stanford_starter.zip from Downloads to your home folder and double-click it, or run cd ~ && unzip ~/Downloads/stanford_starter.zip.
    • Windows (inside Ubuntu/WSL): cd ~ && unzip /mnt/c/Users/<your Windows user name>/Downloads/stanford_starter.zip

  2. Make a new, empty folder and start Claude Code in it:

    mkdir -p ~/setup_check && cd ~/setup_check && claude

  3. Open ~/stanford_starter/setup_check_prompt.md. Copy only the text inside the prompt block, replace <TODO: Your Name your.email@stanford.edu> with your real name and email, then paste it into Claude Code and press Enter. Approve the permission prompts as they come up, reading each one before you say yes.

Claude writes a file called setup_check.txt. It records the versions of your tools, one number taken from a filing (Apple’s total assets in its 10-K for the fiscal year ended September 27, 2025) and the date.

How you know it’s done: setup_check.txt exists in ~/setup_check, it lists a version for each tool, and it gives Apple’s total assets with a link to the 10-K it came from. Open that link yourself, find total assets on the balance sheet, and confirm the number matches. We check every number the agent reports against the source, all session.

If the smoke test fails and you can’t fix it, email me at the address in the pre-class email no later than noon on Sunday, November 1. Include the error message and what you tried. A failed install is easy to fix by email two days ahead and very hard to fix in the room.

3. Download the data

Lab 1 uses three quarters of the SEC’s Financial Statement Data Sets (FSDS): 2016q1, 2020q1 and 2024q1. FSDS groups filings by the quarter the SEC received them, and most firms file their 10-K in February or March, so these files hold mostly fiscal years 2015, 2019 and 2023. Download them now so the room’s wifi can’t hold up the lab.

File Size (zipped)
2016q1.zip 95.5 MB
2020q1.zip 96.6 MB
2024q1.zip 124.3 MB
Total 316.4 MB

Unzipped, the three quarters take about 1.6 GB, most of it in the three num.txt files. Leave at least 3 GB free.

The SEC refuses downloads that don’t say who is asking, and returns “403 Forbidden”. You identify yourself with a User-Agent of the form “Name email”. Make the folder you will use for Lab 1, make it a git repository that ignores the raw data, and download into it. Put your own name and email in the first line:

export SEC_UA="Jane Doe jdoe@stanford.edu"
mkdir -p ~/stanford_lab && cd ~/stanford_lab
git init
echo "fsds/" > .gitignore
bash ~/stanford_starter/download_fsds.sh

The .gitignore line keeps 1.6 GB of raw data out of git. The script downloads each quarter, unzips it into fsds/2016q1/, fsds/2020q1/ and fsds/2024q1/, and deletes the zip. It skips any quarter that is already there, so it is safe to rerun.

If you prefer to run the download by hand, this does the same thing:

export SEC_UA="Jane Doe jdoe@stanford.edu"
mkdir -p ~/stanford_lab/fsds && cd ~/stanford_lab
git init && echo "fsds/" > .gitignore
for q in 2016q1 2020q1 2024q1; do
  curl -fL -A "$SEC_UA" -o "fsds/$q.zip" \
    "https://www.sec.gov/files/dera/data/financial-statement-data-sets/$q.zip"
  unzip -oq "fsds/$q.zip" -d "fsds/$q" && rm "fsds/$q.zip"
  sleep 1
done

How you know it’s done: from ~/stanford_lab, ls fsds/*/ shows three folders, each holding sub.txt, num.txt, pre.txt, tag.txt and readme.htm, and ls -lh fsds/*/num.txt shows three files of roughly 390M to 470M each, and git status does not list fsds/.

5. Read two papers

Read these two papers, about 40 minutes in total. The Readings page has the full citations, which parts to read, and the discussion questions we will use at the end of class.

  • Brodeur et al. (2026), PNAS: a randomized study of human-only, AI-assisted and AI-led teams reproducing published social-science results. PDF
  • Kusumegi et al. (2025), Science: what happened to scientific output after researchers started writing with large language models. Free PDF on arXiv

Hao, Xu, Li and Evans (2026), Nature, is an optional third paper.

How you know it’s done: for each paper you can state its main finding in one sentence, and you have read the two discussion questions for it on the Readings page.

6. Bring a research question

Write down one sentence: a question from your own research that a public SEC dataset (FSDS or EDGAR filings) could at least partly answer. It does not need to be a full paper idea. “How did goodwill impairments change after 2020?” is enough. You will use it in the stretch tier of Lab 1 and in the discussion.

How you know it’s done: the sentence is written somewhere you can copy and paste from during class.
